Build a runnable, interactive desktop-first prototype for improving the UX of HAKI’s Lasco scaffolding design software. Use React, Vite, and Three.js. This is a UX demonstration, not production scaffolding or engineering software.

## Goal

Show how a user can build scaffolding around a building while keeping the 3D model visible and making tools easy to find, scan, and use.

## Main screen

Create a 3D workspace with:

- A central Three.js canvas showing a simple three-storey building on a ground grid. Allow orbit, pan, and zoom.
- A docked, searchable toolkit on the left with clear categories such as Structure, Decking, Access, and Protection.
- A contextual properties panel docked on the right. It should show settings for the selected scaffold part or system, grouped into clear sections.
- A collapsible bottom panel that uses the available width for level-by-level settings and a bill of materials summary.

The left and right panels should stay in consistent positions and be collapsible. The 3D canvas should resize to the space available. Do not open routine tool or settings dialogs over the middle of the model.

## Demo flow

1. Start with the building visible and a clear “Generate starter scaffold” action in the toolkit.
2. When activated, create a simple scaffold around the building using recognizable 3D elements: standards, ledgers, decks, and diagonal braces.
3. Let the user select a scaffold bay or level in the 3D view. Highlight the selection and update the right-hand properties panel.
4. Provide working actions to add or remove a bay or lift, and to toggle decking, guardrails, and a stair tower.
5. When the user chooses a component from the toolkit, show a placement preview snapped to the scaffold. Let the user place it or cancel.
6. Let the user open the bottom panel to compare levels and view a simple parts summary. Selecting a level there should highlight it in the 3D view.

Use sample values and simplified geometry where needed. Any counts, dimensions, or status indicators should be clearly presented as illustrative prototype data, not verified engineering calculations.

## UX and visual direction

Use a calm, professional technical-workspace style with clear text labels, strong visual hierarchy, and restrained HAKI-inspired blue accents. Make dense settings easy to scan: show common options first, group related controls, and place less-used settings under collapsible “Advanced” sections. Keep a small recent or favorite components area for quick access.

## Working requirements

Implement the interactions, not just a static screen. Keep the 3D scene central throughout the demo. Ensure panel controls, scaffold selection, placement preview, and bottom-panel level selection work. Run the app and fix any startup or runtime errors before finishing.
